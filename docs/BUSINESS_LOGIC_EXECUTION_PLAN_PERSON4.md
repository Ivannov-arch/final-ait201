## 1. CODING Tasks (Status: 100% Implemented & Verified)

All local coding and testing deliverables for Person 4 (Base Phase) are **fully implemented and verified**.

### 1.1. Core Rule Engine (`src/engine/rule_engine.py`) — ✅ COMPLETED
* **Status:** Implemented and operational.
* **Functionality:**
  1. **Routing Thresholds:**
     * **Normal Sale (Full Price):** `days_to_expiry > 3` or projected demand $\ge$ batch quantity (0% discount, `retail` channel).
     * **Dynamic Markdown:** `1 < days_to_expiry <= 3` (moderate spoilage risk). Tiered discounts: 15% (DTE=3), 25% (DTE=2), 40% (DTE=1).
     * **Donation:** `days_to_expiry <= 1` (imminent risk of spoilage, 100% discount, `closed_ngo` channel).
  2. **Anti-Moral-Hazard Constraints:**
     * **Channel Segregation:** Donations are strictly assigned to `channel = "closed_ngo"` (partner food banks / NGOs), never on public retail shelves.
     * **Donation Quota Cap (Max 30%):** A store cannot donate more than 30% of its surplus batch volume. Lots exceeding the cap are automatically redirected to aggressive commercial markdown (50% discount) with `moral_hazard_flag = True` to incentivize commercial clearance.
  3. **DataFrame Integration:** Includes `evaluate_lot_dataframe()` to process full batch tables with per-store surplus and donation tracking.
* **File Location:** [`src/engine/rule_engine.py`](file:///c:/Users/evanc/Favorites/Projects/Applied%20Machine%20Learning%20Final/final-ait201/src/engine/rule_engine.py)

## 2. SETUP Tasks That You Must Prepare (External & Cloud)

These remaining setup tasks require your cloud credentials and manual configuration in the Supabase web dashboard:

### 2.1. Create a Supabase Cloud Project
1. Navigate to [supabase.com](https://supabase.com) and sign in.
2. Create a new project:
   * **Project Name:** `dynamic-food-clearing-house` (or `ait201-clearing-house`)
   * **Region:** Singapore (`ap-southeast-1`) — recommended for lowest latency to Malaysia.
   * **Database Password:** Store securely.

### 2.2. Configure Local Environment (`.env`)
1. Create `.env` in the project root (`final-ait201/.env`) by copying `.env.example`:
```bash
Copy-Item .env.example .env
```
2. Retrieve your project credentials from Supabase Dashboard (`Settings -> API`):
   * `Project URL` $\rightarrow$ set to `SUPABASE_URL`
   * `Project API Anon Key` $\rightarrow$ set to `SUPABASE_ANON_KEY`
   * `Project Service Role Key` $\rightarrow$ set to `SUPABASE_SERVICE_ROLE_KEY` (required for ingestion writes)

### 2.3. Deploy SQL Schema to Supabase
1. Open the Supabase **SQL Editor** tab in your browser.
2. Paste and run the contents of [`database/schema.sql`](file:///c:/Users/evanc/Favorites/Projects/Applied%20Machine%20Learning%20Final/final-ait201/database/schema.sql).
3. Paste and run the contents of [`database/seed_receivers.sql`](file:///c:/Users/evanc/Favorites/Projects/Applied%20Machine%20Learning%20Final/final-ait201/database/seed_receivers.sql).
4. Verify in the **Table Editor** that:
   * 5 tables are visible and populated with receiver seed data.
   * RLS policies are enabled (shield icons active).
   * The view `v_dashboard_summary` is queryable.

### 2.4. Execute Live Ingestion
Once the database and `.env` are configured, run the live ETL upload:
```bash
python src/ingest/upload_batches.py
```
